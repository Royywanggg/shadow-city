Date: 2026-10-27. World seed `shadow-city-hero-01`. This record concerns the incremental `HabitScenarioConfigV1` on the existing integrated v5 city. The deterministic experiment data are in [`habits-experiment-results.json`](screenshots/habits-experiment-results.json); the CPU and long-run measurements are in [`habits-performance-results.json`](screenshots/habits-performance-results.json). ## Functional and scientific evidence

`src/simulation/habits/habits.test.ts` covers the new invariants, while the existing v2–v5 and encounter suites cover backward compatibility, legal navigation, ObserverPort isolation and speed-independent replay. After the final code changes, `npm test` passed **201/201 tests in 38 files**, `npm run build` passed its TypeScript check and Vite production build, and `git diff --check` found no whitespace errors. Vite reported a large-bundle advisory; the generated app bundle was about 1.86 MB before gzip.

The three paired Experiment A seeds use 12 citizens and 7,700 Ticks each (two complete later calendar days); the only intervention is `habitWeight` 0.2 versus 1.8. The repeated destination share on those complete days was **0.437→0.477**, **0.363→0.458**, and **0.413→0.472**. The high-weight runs produced fewer total trips (244→199, 221→199, 234→202), and the JSON also records destination diversity, regularity, complete-day denominators, hourly trips and cancellations. These directions were observed after running the model, not asserted as a rule. Experiment B closes each seed's most visited pre-intervention non-home place at Tick 1,920. Citizen and habit state were byte-equal at Tick 1,919 for all three pairs. The first changed destination decisions occurred at T7423, T3042 and T6969 respectively; the common keyed random scheme avoids shifting an unrelated draw merely because one destination is excluded.

The selected, unscripted regression fixture is seed index 1, citizen `citizen-0000`. At Tick 3,042, after the Tick 1,920 place closure, the resident considered the previously visited building but marked it `closed` and selected another reachable eating destination. The actual trip arrived at Tick 3,057 and the activity completed at Tick 3,123. The decision trace includes the real candidate utilities and exclusion reason. The same resident visited the same workplace in both complete later days while other destinations varied; this is an observed partial routine, not a hard-coded schedule. `replayV5` from Tick 0 reproduced the intervention run byte for byte; the browser's past-Tick inspector likewise restored the same intention and decision ID. No special branch in the engine names this citizen or Tick. The fixture choice came from the paired seed search and is recorded in the JSON.

## Performance and long-run audit

The final CPU sample includes the existing Encounter system. Measurements are local Node/Vite SSR runs, not hardware browser FPS. At 100 citizens / 500 Ticks: Tick p50/p95 **2.31/5.46 ms**, replay to Tick 500 **1.40 s**, serialized state **6.19 MB**. At 200: **6.63/10.54 ms**, replay **3.42 s**, state **12.50 MB**. The 20-citizen / 7,700-Tick continuous run was **0.29/1.50 ms** p50/p95, replay **3.16 s**, state **11.97 MB**, with 644 decision traces, 644 activity records, 1,769 habit changes and 94 social interaction events. All three replays were byte-equal. Route-tree query p95 was about **1.5 ms** at 200 citizens; candidate scoring about **0.25 ms**; preparation/scheduling about **0.07 ms**. Current growth is unbounded by design for research replay, so long experiments will need explicit archive/checkpoint policy before large-scale use. JS heap is reported in the raw JSON and is not GPU memory.

The long-run checker tested unique reserved slots, legal surfaces, per-Tick displacement under the configured travel speed, and waiting/planning streaks. It exposed a genuine overnight trap: a resident could not leave a shut Galleria shop because the closed central hall was treated as forbidden even for exit. `canTraverseV2` now permits that shop-to-hall evacuation path while still blocking new entry. The regression test requires a legal shop-to-home route with the shop, mall and mall entry closed. After the fix, the longest observed waiting streak was **3 Ticks** (formerly 1,200). The historical 200-citizen reference targets remain **open**: Tick p95 ≤5 ms and Tick 500 replay ≤2 s are not met. Browser p95 frame interval must be reported separately; a CPU or JS heap number cannot substitute for GPU time or VRAM.

## Open limits

The current 200-citizen CPU Tick/replay target remains unmet, even though measurement and reporting are complete. Route search and existing encounter processing dominate the measured simulation cost; the renderer requires separate profiling. Full sitting and conversational gestures are deferred until there is legitimate simulated seat/gesture state. History is not bounded, and long-run serialized state reached 11.97 MB at only 20 citizens over 7,700 Ticks. The God View has many tabs; the narrow layout and accessibility of the expanded daily-life inspector have not yet been re-reviewed in this workstream. None of these gaps is described as a passed gate.
